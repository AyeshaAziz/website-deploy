# API Contract (`/api/v1`)

Course data is read by the Next.js server directly from the backend API. Registration
requests go through the Next.js BFF: the browser only talks to the BFF, and the BFF either
uses the in-memory mock adapter (`REGISTRATION_API_MODE=mock`) or forwards to the real
backend (`REGISTRATION_API_MODE=live`, `BACKEND_API_URL`).

All payloads are camelCase JSON. Dates are ISO-8601 UTC strings. IDs are strings.

## Envelope

Success:

```json
{ "ok": true, "data": {} }
```

Failure:

```json
{
  "ok": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The registration could not be validated.",
    "fieldErrors": { "email": "Invalid email" },
    "retryAfterSeconds": 3600
  }
}
```

Error codes:

| Code | Meaning | HTTP status |
| --- | --- | --- |
| `VALIDATION_ERROR` | Body or headers are invalid | 400 |
| `DUPLICATE` | Duplicate submission conflict | 409 |
| `RATE_LIMITED` | Too many attempts | 429 |
| `NOT_FOUND` | The requested resource does not exist | 404 |
| `SERVER_ERROR` | Backend unavailable or timeout | 502 |

## Courses

The frontend server calls the backend directly:

```env
BACKEND_API_URL=http://localhost:4000/api/v1
```

Only `PUBLISHED` courses with no `archivedAt` are returned.

### GET `/api/v1/courses`

Returns `{ "ok": true, "data": CourseDTO[] }`, ordered by `sortOrder`, then `title`.

### GET `/api/v1/courses/sitemap`

Returns `{ "ok": true, "data": [{ "urlPath": "...", "updatedAt": "..." }] }`.

### GET `/api/v1/courses/{urlPath}`

Returns `{ "ok": true, "data": CourseDTO }`. Unknown or malformed slugs return `404`
with `NOT_FOUND`.

`CourseDTO` is defined in `@itqasys/core` (`courseDtoSchema`).

## POST `/api/v1/registrations`

Headers:

```
Content-Type: application/json
Idempotency-Key: <uuid v4 generated by the client>
```

The client reuses the same key when retrying the same logical submission. Replaying a
key returns the original result.

Body: the selected track's fields plus `track`.

Tracks: `teacher` and `student`. Both use the same fields:

- `aimsNo` — AIMS number or member code (required)
- `firstName`, `lastName` — required
- `tanzeem` — `boy-5-7` | `girl-5-7` | `atfal-7-11` | `nasirat-7-11` | `atfal-12-15` | `nasirat-12-15` | `khuddam` | `lajna` | `ansar` | `special-needs` | `missionary`
- `country`, `city` — required
- `phone` — required, `+0123456789() -` characters only
- `email`, `confirmEmail` — must match (case-insensitive)
- `teachingExperience` — one of `less-than-one-year` | `over-one-year` | `other` (`teacher` track only)
- `role` — `main-teacher` (`teacher` track only, required)
- `commitDays` — array of `monday` | `tuesday` | `wednesday` | `thursday`, at least one (`teacher` track only, required)
- `availableTimes` — array of `09:00` | `10:00` | `16:00` | `17:00` | `18:00` | `22:00` | `23:00` | `00:00`, at least one (`teacher` track only, required)
- `course` — required, the selected course id
- `courseLanguage` — preferred language for teaching, free text
- `secondLanguage` — optional second language preference
- `consent` — must be `true`

Each registration covers one course. Students may register for additional courses by
submitting again with the same AIMS number and email address.

The canonical validation schemas live in `@itqasys/core` (`registrationSchema` and
`REGISTRATION_SCHEMAS`). The backend must use the same schemas or an equivalent contract
test.

Success (`201`):

```json
{
  "ok": true,
  "data": {
    "reference": "ITQA-TCH-20261020-A1B2C3",
    "track": "teacher",
    "submittedAt": "2026-10-20T12:00:00.000Z",
    "status": "RECEIVED"
  }
}
```

## GET `/api/v1/registrations/{reference}`

Returns the stored registration in the success envelope. Unknown references return
`404` with a `NOT_FOUND` envelope.

## POST `/api/v1/uploads/presign`

Mock-only in v1. Accepts `{ "name", "contentType", "size" }` and returns a mock upload
URL plus a `document` object. The form engine and contracts support file fields, but no
track uses them yet.

## GET `/api/v1/health`

Returns `{ ok: true, data: { status: "ok", mode: "mock" | "live", timestamp } }`.

## Limits

- `POST /registrations`: 10 requests per IP per hour (in-memory limiter).
- `GET /registrations/{reference}`: 60 requests per IP per minute.

## Persistence expectations

- Do not enforce a unique constraint on `(track, normalizedEmail)`; students may register for multiple courses with the same identity.
- Keep `reference` and `idempotency_key` unique.
- Persist the idempotency key with the result and expire it after a reasonable window.
- Store consent timestamp and source (form version) for audit.
- Return the same reference for duplicate idempotency keys.
